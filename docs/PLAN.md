# Circlo: E2EE Social Network, Build Plan for Claude Code

Hand this to Claude Code one phase at a time. Put this file in the repo at `docs/PLAN.md`, and tell Claude Code: *"Read docs/PLAN.md. Implement Phase N only. Write tests first. Stop and summarise when the phase's done-criteria pass."*

## 0. Decisions already made

| Area | Choice | Why |
|---|---|---|
| Backend | Spring Boot 3, Java 21, MySQL 8, Flyway | Your strength. The server only stores ciphertext, so it stays simple |
| Media storage | S3-compatible storage with presigned URLs. Locally: MinIO in Docker on Debian WSL2 | Encrypted blobs go straight from the device to storage, not through the API |
| Local dev environment | Windows + Debian WSL2. **Reuse the existing MySQL already installed in WSL** (no MySQL container). MinIO runs in Docker inside Debian WSL | See Phase 0 for exact setup |
| Mobile | **React Native (Expo, dev builds)**, not two native apps | One codebase, TypeScript, and you can share code with a Next.js web client later. Native-only means maintaining two apps for little gain here |
| UI/UX | **Twitter/X-style timeline** (see section 2A). Own name, logo and colours; copy the interaction patterns, not the brand | It's the most familiar and intuitive timeline UX |
| Styling | **NativeWind** (Tailwind CSS for React Native), current stable release, following its official Expo setup guide | Same Tailwind mental model as your Next.js work |
| App navigation and lists | `expo-router` (bottom tabs plus stacks), `@shopify/flash-list` for the timeline, `expo-image`, `expo-video`, `react-native-reanimated`, `react-native-gesture-handler` | Smooth, long, infinite-scroll feeds |
| Crypto | **One Rust crypto core**, exposed to React Native through `uniffi` (`uniffi-bindgen-react-native`) | Crypto is written and tested once, and runs fast natively (JavaScript crypto is too slow for video). The same core can later compile to WASM for web |
| Messaging | **MLS (RFC 9420) via OpenMLS** for both 1:1 and group chats | One protocol for everything. A 1:1 chat is a 2-member group. Gives forward secrecy and post-compromise security |
| Rust crates | `chacha20poly1305`, `x25519-dalek`, `ed25519-dalek`, `hpke`, `argon2`, `hkdf`, `blake3` or `sha2`, `openmls`, `bip39` | Audited, widely used |

**Rule for Claude Code: the server must never receive plaintext content, plaintext names or emails, private keys, or circle numbers.** If a feature seems to need any of these, stop and ask.

## 0B. Repository: one public monorepo, from day 1

Circlo is a **single monorepo**, and it is **public on GitHub from the first commit**. Being public suits an E2EE app: anyone can check that the app and server do what the privacy promise says. It also means **every commit is published forever**. A secret pushed even once must be treated as leaked: rotate it immediately. Rewriting git history afterwards does not help, because the repo may already have been cloned or scraped.

### Rules that follow from being public

- Every config value that differs per environment is read from environment variables (`CIRCLO_*`), with a committed `.env.example` listing the names and placeholder values.
- Test fixtures use obviously fake values and generated keys; **never real user data, real phone numbers, or keys copied from a real environment**.
- Test key material in `core/` test vectors is fine to commit (it's public by design), but name it clearly (`test_vectors/`, `*_TEST_ONLY`) so scanners and readers know.
- Never paste secrets into issues, PR descriptions, commit messages or CI logs.
- **If a secret is ever pushed:** rotate it first (new password/key, revoke the old one), then clean it up. Rotation is what actually fixes it.
- CI runs `gitleaks` on every pull request as a required check, in addition to GitHub's own push protection.

## 1. Core design: circles as a one-way key chain

Circles are **concentric** (confirmed). A person in circle *k* sees every post addressed to circle *k* or any wider circle (*k*…100). Circle 1 is "only me".

### Key chain

```
C1 = random 32 bytes                (never leaves your own devices)
C(n+1) = HKDF(Cn, info="circlo/v1/circle-step")
```

- A friend placed in circle *k* receives **only** `Ck`, encrypted to their public key (HPKE).
- From `Ck` they can derive C(k+1)…C100 (wider circles), so they can read posts sent to those circles.
- They **cannot** derive `C(k-1)` or anything narrower, because HKDF is one-way.
- **Every friend receives exactly one wrapped key of identical size.** From the server's point of view, every friend looks the same. The server cannot tell which circle anyone is in.
- The friend is never told a circle number. Their app only knows "I hold a key from this person". **This is what lets you add people to circles without them knowing.**

### Posting to circle *n*

1. Generate a random `postKey`. Encrypt the content and media with it.
2. Wrap `postKey` with `Cn`.
3. Tag the post with `keyRef = H("circlo/v1/post-ref" || Cn)`. This is random-looking and doesn't reveal *n*.
4. A reader derives their chain C(k)…C100, computes the refs, and matches the tag.

### Moving people between circles (epochs)

| Change | What happens |
|---|---|
| Move a friend **inward** (9 → 7) | Send them `C7`. Cheap |
| Move **outward** or remove (7 → 9, or unfriend) | Start a new **epoch**: generate a fresh chain, re-wrap one key per remaining friend. This is fine even with 1,000 friends. New posts use the new epoch. Old posts stay readable to anyone who already had access. **No E2EE system can revoke something already seen** |

Your circle assignments (who is in which circle, plus your circle names) live in **your own encrypted "address book" blob**, synced only between your devices.

### Known leaks (accepted, documented)

- Readers fetch encrypted headers for all of an author's posts and decrypt locally. So a friend can tell *that* posts exist which they can't read, but not their content or audience. **Optional later fix:** decoy headers.
- Two friends who compare their app internals could tell whether they are in the same circle.
- The server sees the social graph (who is friends with whom), timestamps, and approximate sizes. Mitigations: pad sizes into buckets, don't log IPs.

## 2. Identity and login (server never sees the password or email)

- **Signup:**
  - The user picks a **handle** (optional, for discovery) and a password.
  - The device generates an identity keypair (X25519 + Ed25519) and a device keypair.
- **Auth key:**
  - `authSeed = Argon2id(password, serverSalt)`.
  - Derive a deterministic Ed25519 keypair from `authSeed`.
  - The server stores **only the public auth key**.
  - Login is a signed challenge.
- **Key backup:**
  - The identity private key, C1 chain root, and address book are encrypted with a key derived from `authSeed` (different HKDF info).
  - The backup is stored as a blob. The server releases it only after a successful signed challenge.
- **Recovery:** a 24-word phrase (BIP39) shown at signup, which encrypts a second copy of the backup. No email reset exists.
- **Profile** (display name, avatar, bio): encrypted with a `profileKey`, which is shared with friends inside the friendship handshake.
- **Upgrade path:** replace challenge-auth with OPAQUE (`opaque-ke`) later if desired.

## 2A. UI/UX: Twitter-style timeline

Build the familiar Twitter/X interaction model under the **Circlo** brand. Do not use X's name, bird/X logo, or its exact blue. Define a brand palette in `tailwind.config.js` as design tokens (`primary`, `surface`, `muted`, `border`, `danger`), and support light and dark mode from day one with NativeWind's `dark:` variants and the system setting.

### App shell
- **Bottom tab bar** with icons only:
  - **Home** (timeline)
  - **Search** (find friends by handle, or scan/share invite QR)
  - **Notifications** (friend requests, replies, likes)
  - **Messages** (DMs and groups)
- **Home header:**
  - Your avatar on the left; tapping it opens a **side drawer** with Profile, Circles, Devices, Settings, Recovery phrase, and Log out.
  - Circlo logo centred (until a real logo exists, use a simple placeholder mark of concentric rings with the "Circlo" wordmark).
  - The header hides on scroll down and reappears on scroll up.
- **Compose floating action button (FAB)**, bottom-right, above the tab bar. It's present on Home and Profile.

### Timeline (Home)
- A single reverse-chronological feed of all readable posts from friends, rendered with FlashList.
- Pull-to-refresh, infinite scroll, and a "New posts" pill that appears at the top when fresh posts arrive.
- **Post card**, top to bottom:
  - avatar
  - **display name** in bold, `@handle`, and relative time (e.g. "2h")
  - text, with links auto-detected
  - media grid: 1 image full-width, 2 side-by-side, 3 as one large plus two stacked, 4 as a 2×2 grid; video with a poster frame and play button, muted autoplay in view
  - action row: **Reply** (count), **Like** (count), **Share-to-DM**, and an overflow menu (Mute, Block; Delete if it's your own post)
- **No reposts/retweets.** Resharing would leak a post beyond its intended circle. Leave this out deliberately.
- **Tap a post** to open the thread view: the original post, then replies in order, with a reply composer docked at the bottom.
- **Media viewer:** full-screen, swipe between images, pinch to zoom, and swipe down to dismiss.
- Decrypted images and thumbnails are shown from local decrypted cache files. Show a skeleton/shimmer while decrypting, and a lock icon placeholder if decryption fails.

### Compose (modal sheet, like Twitter's composer)
- Your avatar and text field with a character counter ring (limit 500), plus Cancel and **Post** buttons.
- **Audience chip** above the text field, like Twitter's "Everyone" selector. Tapping it opens a bottom sheet listing your circles by your labels:
  - Me only (1), Spouse (2), Kids (3–4), Parents & siblings (5), Extended family (6), Closest friends (7), Neighbourhood (8), Work (9), Faded contacts (10), and custom circles up to 100
  - Each row shows "visible to this circle and closer" and a live count of people who can see it
  - Remember the last-used circle as the default
- Media buttons (gallery, camera), with thumbnails of selected items that can be removed or reordered (up to 4 images or 1 video).
- Upload progress shows inline in the timeline as an "uploading…" post card, so the user isn't blocked.

### Who sees circle labels
- **Only the author** sees the audience badge on their own posts (e.g. a small lock icon with "Closest friends+").
- **Readers never see any circle label**, number, or "you're in circle X" indicator anywhere in the UI.

### Profile
- Banner, avatar, display name, `@handle`, bio, and friend count.
- Tabs: **Posts** | **Media** | **Likes** (Likes is visible only on your own profile).
- On a friend's profile, show only what you can decrypt.
- Buttons: **Message**. On your own profile: **Edit profile**.
- **Friend actions are in the overflow menu:** Move to circle (author-only, silent), Unfriend, Block.

### Circles screen (from the drawer)
- A list of your circles with editable labels and member counts.
- Tap a circle to see its members, add or remove people, or drag a person to another circle. All of this is silent: no notification to anyone.
- A **"Preview as…"** option shows your profile exactly as a chosen friend would see it.

### Messages
- Inbox list, Twitter DM style: avatar, name, last-message preview (decrypted locally), time, and unread dot.
- Chat screen with bubbles (yours right-aligned in the primary colour, theirs left), date separators, image/video attachments, a typing composer, and long-press to react or delete for yourself.
- A "New message" FAB lets you pick one friend (DM) or several friends (group, with a group name and avatar).

### Notifications tab
- Friend requests (Accept/Decline inline), replies, likes, and group invites, in a Twitter-style list grouped by day.
- Push notifications never contain content (see Phase 10). The app fetches and decrypts the details when opened.

### Polish
- Haptic feedback on like/post.
- Optimistic likes and replies.
- Respect the system font size.
- Accessibility labels on all icon buttons.
- Empty states with an illustration and call to action (e.g. "Invite your first friend").

## 4. Phased build

Each phase lists **what to build**, then **done when**.

### Phase 0: Repo, spec, local infrastructure (Windows + Debian WSL2)

Prerequisite: you have done section 0B steps 1–5 (repo created, `.gitignore` and pre-commit hooks in place, pushed to a public GitHub repo, protections on). The repo lives **inside the WSL filesystem** (`~/code/circlo`), not under `/mnt/c/`, because cross-filesystem I/O is very slow.

Claude Code then scaffolds the layout from section 0B: `core/`, `server/`, `app/`, `docs/`, `infra/`, the root `README.md`, `SECURITY.md`, `CONTRIBUTING.md`, `LICENSE`, `Makefile`, `.gitleaks.toml`, `.editorconfig`, a `CLAUDE.md` in each subfolder, `.github/workflows/` (CI per folder with path filters, plus a required `gitleaks` job), `.github/dependabot.yml` (Cargo, Maven, npm, GitHub Actions) and `.github/CODEOWNERS`.

#### 0.1 WSL networking (do once, on Windows)
Phones and emulators must reach the API and MinIO. Create `%UserProfile%\.wslconfig`:
```ini
[wsl2]
networkingMode=mirrored
```
Then run `wsl --shutdown` in PowerShell and reopen Debian. With mirrored mode, services in WSL listen on the Windows host's LAN IP. Allow ports **8080** (API), **9000** (MinIO S3) and **9001** (MinIO console) in Windows Defender Firewall for the Private profile.

#### 0.2 Existing MySQL (do not install another)
Claude Code must **not** add a MySQL container. Use the MySQL already running in WSL:
```bash
sudo service mysql start        # or: sudo systemctl start mysql (if systemd is enabled)
sudo mysql <<'SQL'
CREATE DATABASE IF NOT EXISTS circlo      CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE IF NOT EXISTS circlo_test CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'circlo'@'localhost' IDENTIFIED BY 'change-me';  -- use your own password here; put it only in server/.env.local
GRANT ALL PRIVILEGES ON circlo.*      TO 'circlo'@'localhost';
GRANT ALL PRIVILEGES ON circlo_test.* TO 'circlo'@'localhost';
FLUSH PRIVILEGES;
SQL
```
- Spring Boot runs in WSL and connects to `jdbc:mysql://localhost:3306/circlo`.
- Integration tests use the `circlo_test` database: Flyway clean and migrate before each test class. Never touch `circlo` from tests.
- Credentials come from `server/.env.local` (git-ignored, `CIRCLO_`-prefixed variables), loaded by Spring profile `local`. Commit a `.env.example` only.

#### 0.3 Docker Engine on Debian WSL (for MinIO)
If Docker Desktop is installed on Windows, enable *Settings → Resources → WSL Integration → Debian* and skip to 0.4. Otherwise install Docker Engine directly in Debian:
```bash
# enable systemd for WSL (needed for the docker service)
echo -e "[boot]\nsystemd=true" | sudo tee /etc/wsl.conf
# then in PowerShell: wsl --shutdown, and reopen Debian

sudo apt-get update && sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/debian $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker $USER   # log out and back in
docker run --rm hello-world
```
If MySQL was started with `service` before systemd was enabled, re-enable it after the switch: `sudo systemctl enable --now mysql`.

#### 0.4 MinIO via Docker Compose
`infra/docker-compose.yml` contains **MinIO only**:
```yaml
name: circlo
services:
  minio:
    image: minio/minio:latest
    container_name: circlo-minio
    command: server /data --console-address ":9001"
    ports: ["9000:9000", "9001:9001"]
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
      MINIO_SERVER_URL: http://${LAN_IP}:9000   # presigned URLs must use an address phones can reach
    volumes: ["circlo-minio-data:/data"]
    restart: unless-stopped
  minio-init:
    image: minio/mc:latest
    container_name: circlo-minio-init
    depends_on: [minio]
    entrypoint: >
      /bin/sh -c "
      until mc alias set local http://minio:9000 $${MINIO_ROOT_USER} $${MINIO_ROOT_PASSWORD}; do sleep 2; done;
```
